# Branding and Canonical Rules

Read and follow [`../../AGENTS.md`](../../AGENTS.md). It is the canonical instruction source.

ZinuRooms should remain capable of future white-label/property-brand configuration, but this does not authorise ad-hoc theme rewrites or hardcoded per-hotel branding.

- Use shared, named design tokens and branding configuration.
- Do not duplicate colours, logos or brand rules across pages/apps.
- Preserve the default ZinuRooms brand unless the assigned workstream explicitly changes branding architecture.
- A white-label change must define tenant scope, asset storage, accessibility, fallback behaviour, caching and web/mobile compatibility.
- Do not combine branding redesign with unrelated fixes.
